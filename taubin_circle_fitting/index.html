Step 1 — The Problem

What Are We Fitting?

Given $N$ noisy 2D points, find the circle that best passes through them. This is core to estimating road curvature from sensor data in autonomous driving.

The Algebraic Circle Equation

Any circle in 2D satisfies:

$$a(x^2+y^2)+bx+cy+d=0$$

The vector $\mathbf{v}=[a,b,c,d]^T$ fully encodes the circle. From it:

$$\text{Center}=\!\left(-\tfrac{b}{2a},\,-\tfrac{c}{2a}\right),\quad R=\frac{\sqrt{b^2+c^2-4ad}}{2|a|}$$
The Residual for Each Point

For a noisy point $(x_i,y_i)$ that doesn't lie exactly on the circle, define the algebraic residual:

$$F_i = a(x_i^2+y_i^2)+bx_i+cy_i+d$$

We want $\mathbf{v}$ that makes all $F_i$ small simultaneously — i.e., minimize:

$$\min_{\mathbf{v}}\sum_{i=1}^N F_i^2 = \min_{\mathbf{v}}\|M\mathbf{v}\|^2$$
The Design Matrix $M$ — What Both Implementations Build

Stack all residuals into a matrix-vector product. Each row = one point:

$$M = \begin{pmatrix} x_1^2+y_1^2 & x_1 & y_1 & 1 \\ x_2^2+y_2^2 & x_2 & y_2 & 1 \\ \vdots & \vdots & \vdots & \vdots \\ x_N^2+y_N^2 & x_N & y_N & 1 \end{pmatrix},\qquad M\mathbf{v}=\begin{pmatrix}F_1\\F_2\\\vdots\\F_N\end{pmatrix}$$
💡
Both implementations start here.

Impl 1 stores the full $N\times4$ matrix. Impl 2 computes only the $4\times4$ product $M^TM$ directly from dot products — same math, $O(N)$ vs $O(1)$ memory.

Step 2 — The Core Problem

Why We Can't Just Minimize $\|M\mathbf{v}\|^2$

The unconstrained minimum is always $\mathbf{v}=\mathbf{0}$. We must pin down the scale of $\mathbf{v}$ with a constraint.

⚠️
The Trivial Solution Problem

$\mathbf{v}=[0,0,0,0]^T$ gives $\|M\mathbf{v}\|^2=0$ — a perfect score with zero geometric content. Any optimizer will find this unless we forbid it.

❌ Option A — Euclidean Norm (Impl 1)

The simplest fix: require the parameter vector to have unit length.

$$\|\mathbf{v}\|^2 = a^2+b^2+c^2+d^2 = 1$$

Easy to enforce — just take the smallest eigenvector of $M^TM$. But it treats $a$, $b$, $c$, $d$ as if they have the same units, which they don't.

🚨
Bias:

$a$ scales $r^2$, while $d$ is a constant offset. Mixing them is like adding meters to seconds.

✅ Option B — Geometric Constraint (Impl 2)

Fix a quantity with direct geometric meaning — the discriminant of the circle:

$$b^2+c^2-4ad = 1$$

This is the Bookstein constraint. It controls the circle's shape, not an arbitrary algebraic scale.

✅
Scale-invariant:

Results don't change if you zoom in or out on your data. Geometrically consistent.

Step 3 — Implementation 1

The Euclidean Constraint: A Standard Eigenproblem

With $\|\mathbf{v}\|^2=1$, the constrained optimization reduces to a familiar symmetric eigenproblem.

1

Set Up the Lagrangian

To minimize $\|M\mathbf{v}\|^2$ subject to $\|\mathbf{v}\|^2=1$, introduce a Lagrange multiplier $\lambda$:

$$\mathcal{L}(\mathbf{v},\lambda) = \mathbf{v}^T M^TM\,\mathbf{v} - \lambda\!\left(\mathbf{v}^T\mathbf{v}-1\right)$$
2

Differentiate and Set to Zero

$$\frac{\partial\mathcal{L}}{\partial\mathbf{v}} = 2M^TM\,\mathbf{v} - 2\lambda\mathbf{v} = 0 \;\Longrightarrow\; M^TM\,\mathbf{v} = \lambda\,\mathbf{v}$$

This is a standard symmetric eigenproblem. The objective value equals $\lambda$, so we pick the smallest eigenvalue → smallest eigenvector.

3

Code — Impl 1

impl1_naive.cpp 
// Build N×4 design matrix M
Eigen::MatrixXd M = Eigen::MatrixXd::Ones(N, 4);
M.col(0) = x*x + y*y;
M.col(1) = pts.col(0);
M.col(2) = pts.col(1);

// ⚠️  Heuristic row-weighting — not the true Taubin method
auto w = 2 * (x*x + y*y).sqrt();   // ≈ gradient norm
M.array().colwise() /= w;          // divide each row

// Standard symmetric eigenproblem: M^T M v = λ v
Eigen::Matrix4d mTM = M.transpose() * M;
Eigen::SelfAdjointEigenSolver<Eigen::Matrix4d> solver(mTM);

// col(0) = smallest eigenvalue (SelfAdjoint sorts ascending)
auto v = solver.eigenvectors().col(0);

// Curvature from recovered parameters
auto k = 2*v(0) / sqrt(v(1)*v(1) + v(2)*v(2) - 4*v(0)*v(3));
⚠️
What's wrong with the weighting?

Dividing rows by $w_i=2r_i$ then solving $\tilde{M}^T\tilde{M}\mathbf{v}=\lambda\mathbf{v}$ is not the Taubin method. The true Taubin formulation requires a separate constraint matrix $C$ — not a row-weighting. This conflation produces biased curvature estimates, especially when points are far from the origin.

Step 4 — The Key Insight

Why the Discriminant Is the Right Constraint

The discriminant $\Delta=b^2+c^2-4ad$ is not arbitrary — it appears directly in the radius formula and controls the circle's geometry.

Connecting $\Delta$ to Geometry

Recall the radius formula:

$$R = \frac{\sqrt{b^2+c^2-4ad}}{2|a|} = \frac{\sqrt{\Delta}}{2|a|}$$

And curvature $\kappa=1/R$:

$$\kappa = \frac{2|a|}{\sqrt{\Delta}} = \frac{2|a|}{\sqrt{b^2+c^2-4ad}}$$

Setting $\Delta=1$ fixes the geometric scale — not an arbitrary algebraic one.

The Constraint Matrix $C$

We can write $\Delta=\mathbf{v}^TC\mathbf{v}$ where:

$$C = \begin{pmatrix} 0&0&0&-2\\ 0&1&0&0\\ 0&0&1&0\\ -2&0&0&0 \end{pmatrix}$$

Verify: $\mathbf{v}^TC\mathbf{v} = b^2+c^2+(-2)(ad+da) = b^2+c^2-4ad = \Delta$ ✓

📝

Impl 2 uses $C(0,3)=C(3,0)=+2$ — a sign convention difference. Mathematically equivalent.

Intuition: Why Does This Fix the Bias?
Euclidean Constraint

$a^2+b^2+c^2+d^2=1$ treats all parameters equally. But $a$ scales $r^2$ while $d$ is a constant — they live in different spaces. Results change with data scale.

Bookstein Constraint

$b^2+c^2-4ad=1$ only involves combinations that appear in the radius formula. It's a constraint on the circle shape, not the parameter vector scale.

Scale Invariance

If you scale all coordinates by $s$, the Bookstein constraint transforms consistently. Zoom in or out — the fitted curvature stays the same.

Step 5 — Implementation 2

The Generalized Eigenproblem: Correct Taubin

Replacing $I$ with $C$ in the constraint transforms the standard eigenproblem into a generalized one — one mathematical change with profound geometric consequences.

1

New Lagrangian with $C$

$$\mathcal{L}(\mathbf{v},\lambda) = \mathbf{v}^T M^TM\,\mathbf{v} - \lambda\!\left(\mathbf{v}^TC\mathbf{v}-1\right)$$
2

Differentiate → Generalized Eigenproblem

$$\frac{\partial\mathcal{L}}{\partial\mathbf{v}} = 2M^TM\,\mathbf{v} - 2\lambda C\mathbf{v} = 0 \;\Longrightarrow\; \boxed{M^TM\,\mathbf{v} = \lambda\,C\,\mathbf{v}}$$

Compare to Impl 1: we simply replaced $I$ with $C$. That single substitution encodes all the geometric meaning.

3

Convert to Standard Form via $C^{-1}$

Multiply both sides by $C^{-1}$:

$$C^{-1}M^TM\,\mathbf{v} = \lambda\,\mathbf{v}$$

Now it's a standard eigenproblem for $C^{-1}M^TM$. But this matrix is not symmetric (even though $M^TM$ is), so we must use a general eigensolver — eigenvalues may be complex.

4

Which Eigenvalue to Pick?

Substituting $\mathbf{v}^TC\mathbf{v}=1$ back into the objective:

$$\mathbf{v}^TM^TM\,\mathbf{v} = \lambda\underbrace{\mathbf{v}^TC\mathbf{v}}_{=1} = \lambda$$

The objective value equals $\lambda$. To minimize algebraic error: pick the smallest positive real eigenvalue. Negative $\lambda$ → imaginary circle (invalid). Complex $\lambda$ → numerical artifact (skip).

// z_i = x_i² + y_i²
const Eigen::VectorXd z = x.array().square() + y.array().square();

// Compute 9 scalar moments — never store the N×4 matrix
const double Mzz = z.dot(z) * inv_N;   // (1/N) Σ z²

const double Myz = y.dot(z) * inv_N;
const double Mxx = x.dot(x) * inv_N;
const double Myy = y.dot(y) * inv_N;
const double Mxy = x.dot(y) * inv_N;
const double Mzo = z.mean();
const double Mxo = x.mean();
const double Myo = y.mean();

M << Mzz, Mxz, Myz, Mzo,    // 4×4, identical to M^T M
   Mxz, Mxx, Mxy, Mxo,
   Myz, Mxy, Myy, Myo,
   Mzo, Mxo, Myo, 1.0;
Step 6 — Engineering Safeguards

What Makes Impl 2 Production-Ready

Beyond the math, three critical guards are added that Impl 1 completely lacks. Each prevents a real failure mode.

A

Centroid Subtraction — Numerical Stability

Before any computation, subtract the mean of all points:

$$\tilde{x}_i = x_i - \bar{x},\quad \tilde{y}_i = y_i - \bar{y}$$

Why? If your circle is centered at $(1000,1000)$ with radius $4$, then $x_i^2+y_i^2\approx2\times10^6$ while the geometry varies by only $\pm4$. Floating-point arithmetic loses all precision in the subtraction. Centering makes all values small and the computation stable.

taubin_curvature.hpp — taubin_curvature() 
const Eigen::Vector2d centroid = points.colwise().mean();
const Eigen::MatrixX2d pts_c = points.rowwise() - centroid.transpose();
// ... all fitting done on pts_c ...
// shift circle center back to original frame:
result.center = center_c + centroid;
B

Collinearity Check — Prevent Division by Zero

Before fitting, check if points are nearly on a straight line using the SVD singular value ratio:

$$\text{ratio} = \frac{\sigma_2}{\sigma_1} \approx 0 \;\Rightarrow\; \text{points are collinear (straight line)}$$

Singular values $\sigma_1,\sigma_2$ measure spread in each direction. A line has spread in only one direction → $\sigma_2\approx0$. Without this guard, fitting a circle to collinear points gives $R\to\infty$, causing $\kappa=1/R\to0$ via division by near-zero — numerically explosive.

taubin_curvature.hpp — collinearity_ratio() + early exit 
// SVD of centered points
const Eigen::JacobiSVD<Eigen::MatrixX2d> svd(pts_c, Eigen::ComputeThinU | Eigen::ComputeThinV);
const double ratio = svd.singularValues()[1] / svd.singularValues()[0];

if (ratio < straight_threshold) {   // nearly collinear
result.is_straight = true;
result.kappa = 0.0;
result.radius = std::numeric_limits<double>::infinity();
return result;                     // early exit, no eigenproblem
}
C

Signed Curvature — MPC Needs Direction

Impl 1 always returns positive $\kappa$. For MPC lateral control, the sign tells you which way to steer. Use the shoelace formula (signed area of the point polygon):

$$A = \sum_{i=0}^{N-2}(x_i y_{i+1} - x_{i+1} y_i)$$ $$\text{sign}(\kappa) = \text{sign}(A): \quad A>0\Rightarrow\text{CCW (left turn)},\quad A<0\Rightarrow\text{CW (right turn)}$$
taubin_curvature.hpp — curvature_sign() + application 
double signed_area = 0.0;
for (int i = 0; i < N-1; ++i)
signed_area += pts(i,0)*pts(i+1,1) - pts(i+1,0)*pts(i,1);
const double sign = (signed_area >= 0.0) ? 1.0 : -1.0;

result.kappa = sign * kappa_abs;  // signed curvature

The Core Insight in One Sentence

Impl 1 uses the right objective ($\|M\mathbf{v}\|^2$) but the wrong constraint ($\|\mathbf{v}\|=1$). Impl 2 replaces the constraint with one that has direct geometric meaning ($\mathbf{v}^TC\mathbf{v}=1$), which changes a plain eigenproblem into a generalized one — and adds all the engineering guards needed for a production autonomous driving system.
